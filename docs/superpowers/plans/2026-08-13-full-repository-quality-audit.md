# 全仓代码质量巡检与自动修复计划

## 目标

在方案 A 的 11 项功能完成并通过验收后，对前端 Vue、Node/Express 服务、Python/FastAPI AI 服务、数据库迁移与种子、自动化脚本进行一次独立的全仓质量巡检。巡检以实际代码、构建结果、测试结果和浏览器运行证据为准，不把单纯的健康检查或静态搜索当成完成依据。发现问题后先补充或调整测试，再做最小范围修复，并循环执行针对性测试和全量回归。

## 执行边界

- 保留工作区中已有且与本轮无关的用户改动，不做重置、清理或大范围格式化。
- 优先修复可复现的缺陷、错误处理漏洞、接口契约漂移、资源泄漏、明显性能问题和影响可维护性的重复代码。
- 对只有风格偏好、缺少证据或可能改变产品行为的问题，只记录风险，不进行主观重写。
- 不修改生产密钥，不删除真实数据，不执行破坏性数据库操作。

## 巡检步骤

1. 盘点三个运行时的脚本、入口、配置和测试覆盖，记录当前基线及工作区边界。
2. 执行前端 lint、TypeScript、单元测试和生产构建；检查路由、异步请求、错误态、无障碍与包体积警告。
3. 执行 Node 服务 lint、TypeScript、完整单元测试；重点定位 Jest 未退出、定时器/连接泄漏、路由与控制器契约、权限边界和日志泄露。
4. 执行 Python AI 服务测试、编译与可用的静态检查；核对超时、缓存、降级、风险识别和外部搜索边界。
5. 扫描硬编码地址、TODO/FIXME、空异常处理、调试日志、危险类型断言、明文凭据和重复实现，并逐项人工确认是否构成真实问题。
6. 为确认的问题添加回归测试或验证脚本，按风险和影响排序进行最小修复。
7. 重新运行三端全量测试、生产构建、数据库只读验证和关键浏览器链路，直至无新增失败。
8. 输出变更、证据、未解决风险和建议，明确区分已修复、仅告警与环境限制。

## 完成标准

- 三端全量自动化测试全部通过。
- 前端与 Node 生产构建通过，Python 源码编译通过。
- 新确认的缺陷有对应测试或可重复验证证据。
- 关键管理端、知识库、通知、AI 助手和情绪分析浏览器链路无请求失败与控制台错误。
- 不覆盖用户既有改动，最终报告能定位到具体文件与验收产物。
