## 2. 产品目标

在 P0/v1.0 建立的量表测评与风险个案管理基础上，引入 AI 能力增强平台智能化水平：

1. **Prompt 模板管理**：管理员可配置、管理 AI 提示词模板，支持多场景分类。
2. **AI 量表解读**：学生提交量表后，可一键获取 AI 生成的测评结果解读，帮助理解量表含义。
3. **AI 情绪报告**：基于学生情绪记录数据，生成周度/月度 AI 情绪分析报告。
4. **AI 基础设施**：建立可配置的 AI 调用客户端，支持 DeepSeek API，具备鉴权、重试、降级能力。

## 4. 功能需求

### 4.1 Prompt 模板管理

#### 4.1.1 模板分类

| 分类编码 | 说明 | 使用场景 |
|---|---|---|
| `assessment_interpretation` | 量表解读 | AI 解读测评结果 |
| `mood_report` | 情绪报告 | AI 生成周报/月报 |
| `counseling` | 心理咨询 | 预留 |
| `recommendation` | 内容推荐 | 预留 |

#### 4.1.2 模板结构

每个 Prompt 模板包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | VARCHAR(100) | 模板名称，唯一 |
| `category` | VARCHAR(50) | 分类编码 |
| `system_prompt` | TEXT | 系统提示词（角色设定） |
| `user_prompt_template` | TEXT | 用户提示词模板，支持 `{{variable}}` 占位 |
| `variables` | JSON | 可用变量定义及说明 |
| `model` | VARCHAR(50) | 推荐模型，默认 `deepseek-chat` |
| `temperature` | DECIMAL(3,2) | 温度参数，默认 0.70 |
| `max_tokens` | INT | 最大输出 token，默认 2048 |
| `is_active` | TINYINT(1) | 是否启用 |
| `sort_order` | INT | 排序 |

#### 4.1.3 模板 CRUD API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/prompts/` | `prompt.manage` | 模板列表 |
| GET | `/api/prompts/:id` | `prompt.manage` | 模板详情 |
| POST | `/api/prompts/` | `prompt.manage` | 创建模板 |
| PUT | `/api/prompts/:id` | `prompt.manage` | 更新模板 |
| DELETE | `/api/prompts/:id` | `prompt.manage` | 删除模板 |

所有操作写入审计日志。

#### 4.1.4 模板变量替换

`user_prompt_template` 中的 `{{variableName}}` 占位符在调用时被替换为实际值。例如：

```
模板：请对以下 {{scaleName}} 测评结果进行解读。总分：{{totalScore}}/{{maxScore}}。
替换后：请对以下 PHQ-9 测评结果进行解读。总分：12/27。
```

### 4.2 AI 客户端

#### 4.2.1 配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AI_ENABLED` | `false` | AI 功能总开关 |
| `DEEPSEEK_API_KEY` | — | DeepSeek API 密钥 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | DeepSeek API 地址 |
| `AI_TIMEOUT` | `30000` | 请求超时(ms) |
| `AI_MAX_RETRIES` | `3` | 失败重试次数 |
| `AI_MODEL_MOOD_ANALYSIS` | `deepseek-chat` | 情绪分析模型 |
| `AI_PROXY_RATE_LIMIT_MAX` | `30` | 15分钟内最大请求数 |

#### 4.2.2 核心函数

**`callChatCompletion(messages, options)`** — 调用 DeepSeek Chat Completion API：

- 输入：标准 `{ role, content }` 消息数组
- 输出：纯文本响应内容
- 鉴权：`Authorization: Bearer ${DEEPSEEK_API_KEY}`
- 错误处理：区分 401（Key 无效）、429（频率超限）、其他错误
- AI 未启用时抛出 `AiServiceError`

**`callWithTemplate(templateName, variables, options)`** — 模板驱动调用：

- 从数据库加载指定名称的已启用模板
- 用 `variables` 替换模板中的占位符
- 组装 system + user 消息，调用 `callChatCompletion`
- 模板不存在时抛出明确错误

#### 4.2.3 降级策略

- `AI_ENABLED=false` 时，所有 AI 端点返回提示信息而非报错
- 树洞场景固定使用本地温柔文案，不依赖外部 AI 服务

### 4.3 AI 量表解读

#### 4.3.1 API

`POST /api/ai/interpret`

**请求体**：

```json
{
  "scaleName": "PHQ-9 抑郁症筛查量表",
  "scaleType": "depression",
  "totalScore": 12,
  "maxScore": 27,
  "itemScores": [
    { "label": "兴趣减退", "score": 2 },
    { "label": "情绪低落", "score": 3 }
  ],
  "riskLevel": "moderate"
}
```

**响应**：

```json
{
  "code": 0,
  "message": "AI 解读生成成功",
  "data": {
    "content": "根据PHQ-9测评结果，您的总分...",
    "generatedAt": "2026-07-16T12:00:00.000Z"
  }
}
```

**错误码**：

| 状态码 | 说明 |
|---|---|
| 503 | AI 服务未启用 |
| 404 | Prompt 模板不存在 |
| 500 | AI 解读生成失败 |

#### 4.3.2 业务流程

```
学生提交量表 → 查看结果页 → 点击"AI 智能解读"
  → 前端 POST /api/ai/interpret
  → aiAssessmentService 根据 scaleType 选择模板
  → callWithTemplate 填充变量 → callChatCompletion → DeepSeek API
  → 返回解读文本 → 前端渲染（含 AI 免责声明）
```

#### 4.3.3 前端展示

- 测评结果页（`QuestionnaireResult.vue`）底部增加"AI 智能解读"按钮
- AI 解读内容以 Markdown 渲染
- 底部显示免责声明："以上内容由 AI 生成，仅供参考，不构成医疗建议。"
- 支持刷新重新生成

### 4.4 AI 情绪报告

#### 4.4.1 API

`POST /api/ai/report`

**请求体**：

```json
{
  "userName": "张三",
  "dateRange": "2026-07-10 ~ 2026-07-16",
  "recordCount": 7,
  "primaryEmotions": "开心, 平静",
  "averageIntensity": 6.5,
  "mostFrequentMood": "开心",
  "type": "weekly",
  "trend": "情绪强度呈上升趋势",
  "highlights": "周三达到情绪高峰",
  "lowPoints": "周一情绪较低",
  "emotionDistribution": "开心 40%, 平静 30%, 焦虑 20%"
}
```

**响应**：

```json
{
  "code": 0,
  "message": "AI 报告生成成功",
  "data": {
    "content": "# 本周情绪报告\n\n亲爱的张三...",
    "generatedAt": "2026-07-16T12:00:00.000Z"
  }
}
```

#### 4.4.2 报告类型

| 类型 | 模板名称 | 说明 |
|---|---|---|
| `weekly` | 周度情绪报告 | 一周情绪总结与分析 |
| `monthly` | 月度情绪报告 | 月度情绪趋势与洞察 |

### 4.5 限流

## 6. 非功能需求

### 6.1 资源约束

沿用 2 核 2G 配置，AI 调用为外部 API，不额外占用服务器资源：

- AI 请求超时 30 秒（可配置）
- 单次请求最大 token 2048（可配置）
- 15 分钟内最多 30 次 AI 请求（可配置）

### 6.2 安全

- AI API Key 通过环境变量配置，不写入代码或提交 Git
- 审计日志记录 Prompt 模板的创建/更新/删除操作
- 前端 AI 解读内容标注"仅供参考，不构成医疗建议"
- AI 请求不包含学生真实姓名（后端填充脱敏信息）

### 6.3 可用性

- AI 功能通过 `AI_ENABLED` 环境变量控制总开关，关闭时不影响核心功能
- AI 调用失败时返回明确错误信息，不阻塞页面
- 树洞场景使用本地文案降级，不依赖外部 AI

## 8. 实施总结

V1.1 在 P0 核心业务闭环之上，以最小侵入方式引入 AI 能力：

1. **架构约束**：AI 调用完全通过 `callChatCompletion` 统一出口，不分散在业务代码中
2. **模板驱动**：所有 AI 输出通过 Prompt 模板控制，管理员可调整提示词而无需修改代码
3. **配置化**：模型选择、温度、Token 数等参数均可通过模板配置，无需硬编码
4. **降级优先**：AI 功能关闭时不影响核心业务，前端展示优雅降级

## 9. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| AI API 不可用 | 解读/报告功能不可用 | 总开关 `AI_ENABLED`，前端显式提示 |
| AI 生成不当内容 | 用户误解或不适 | Prompt 模板约束输出范围，前端免责声明 |
| API Key 泄露 | 费用损失 | 环境变量配置，不提交 Git |
| API 调用成本 | 运营费用 | 限流 30 次/15 分钟，Token 上限 2048 |
