## 2. 需要什么程度的重构

建议采用“轻量修复 + 定向重构”，不做整体重写。

可以理解为：

- 60%：修复稳定性、测试、安全和启动问题。
- 30%：收敛 API、数据库和核心模块边界。
- 10%：删除无效代码、统一命名和目录。

保留以下资产：

- Vue 3、Pinia、Vue Router 和现有页面框架。
- Express 的 Route、Controller、Model 基础分层。
- 当前 UI 风格和大部分业务页面。
- 已有情绪、问卷、社区、活动、资源等功能。
- SQLite 中已有的主要业务实体。

重点重构以下边界：

1. API 响应契约。
2. 登录恢复和问卷核心链路。
3. SQLite 数据库结构与迁移方式。
4. 测试数据库和测试数据初始化。
5. 心理危机识别及内容安全。
6. 后续 AI 服务的统一接入边界。

暂时不要：

- 重写所有页面。
- 更换 Vue、Express 或数据库技术。
- 一次性拆分所有大文件。
- 为了“架构高级”引入微服务、消息队列、DDD 等复杂方案。
- 同时维护两套数据库实现。

## 3. 优化事项的 P0/P1/P2

| 优先级 | 目标 | 主要内容 |
|---|---|---|
| P0 | 系统可信、核心功能可运行 | API 契约、登录恢复、问卷、启动脚本、测试初始化、仓库清理、XSS、心理安全、SQLite 收敛 |
| P1 | 代码可维护、方便继续开发 | 核心大文件拆分、Service/Repository 边界、统一迁移、类型定义、集成测试、错误处理 |

### P0：必须先完成

建议形成一个“工程稳定化版本”。

1. 统一 API 契约

建议后端统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

前端的领域 API 层统一返回业务数据，页面不再理解 `code/data` 包装结构。

也就是：

```text
后端统一包装
→ request.ts 处理错误和解包
→ src/api 返回明确类型
→ 页面只使用业务对象
```

2. 修复五条核心链路

- 登录。
- 页面刷新后的身份恢复。
- 情绪记录和查询。
- 问卷加载、提交、结果和历史记录。
- 报告与趋势展示。

3. 数据库收敛

- 毕业设计阶段选择一个唯一数据库。
- 建立唯一 Schema/迁移入口。
- 禁止 Model 在运行过程中自行建表。
- 测试使用独立临时数据库。
- 保存问卷逐题答案，保证结果可追溯。
- 清理仓库中的数据库、WAL、SHM 和虚拟环境追踪。

- 服务端清洗课程 HTML，或者改用安全 Markdown。
- 建立基础危机关键词识别。
- 高风险输入必须展示专业求助和人工转介提示。
- AI 或咨询服务失败时返回安全降级内容。
- 明确“辅助工具，不构成医疗诊断”。

P0 完成标准不以“代码写完”为准，而是：

- 干净环境能够初始化。

## 4. 优化后先做闭环还是 AI

推荐顺序是：

```text
定向优化
→ 核心业务闭环
→ 基础 AI 接入
→ AI 个性化和管理分析
```

核心闭环必须先于完整 AI 功能，因为 AI 需要稳定的数据输入：

- 用户身份。
- 情绪记录。
- 历史趋势。
- 问卷结果。
- 风险状态。
- 建议历史。

如果这些数据结构和接口还不稳定，AI 接入后会不断返工。

但在优化阶段就应该设计好 AI 接口边界，避免后续再次改架构。推荐调用链是：

```text
前端
→ Node.js 后端鉴权、脱敏和风险识别
→ Python AI 服务
→ Node.js 结构化校验与安全审核
→ 前端展示
```

不建议继续让前端直接调用 Python AI 服务。

AI 应当成为核心闭环中“个性化建议”的增强能力，而不是独立堆叠出来的展示功能。
