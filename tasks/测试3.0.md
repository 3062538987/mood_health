## 4. P0 阻断缺陷

### P0-01：活动迁移与心情仓储不一致，合法新增/更新必然失败

**现象**：登录成功后调用 `POST /api/moods/record`，合法 payload 返回 HTTP 500“服务器错误”。

**代码链**：

1. `mood_health_server/src/db/migrations/0080_create_moods.up.sql:1` 创建 `moods`，实际列只有 `id/user_id/note_ciphertext/trigger_ciphertext/recorded_at/created_at/updated_at`。
2. `mood_health_server/src/repositories/moodRepository.ts:229` 的 INSERT 写入 `include_note`；同文件约 467 行的 UPDATE 同样写入。
3. 旧文件 `mood_health_server/migrations/002_create_analysis_jobs.sql:26` 曾 `ALTER TABLE moods ADD COLUMN include_note`，但当前 runner 读取的是 `src/db/migrations`，该旧文件不会被当前迁移状态命令应用。
4. 隔离 DB 完成 31 个活动迁移后 `DESCRIBE moods` 仍无 `include_note`，排除“只是漏跑最新活动迁移”。

**影响**：核心心情记录新增与更新不可用；页面、趋势、AI 分析、毕业演示主链路均被阻断。

**判定**：确定性产品缺陷，不是测试夹具问题。

### P0-02：AI 分析链路在接口、表结构和调度三层同时断裂

**现象**：`POST /api/mood-analyses` 返回 500；FastAPI `POST /api/analyze/mood` 返回 404；实际 8001 无服务。

**代码链**：

- `moodAnalysisDataService.ts:181+` 查询/写入 `mood_analysis_versions`，活动迁移没有该表。
- `analysisDispatcher.ts:52+` 读取已不存在的 `mood_records`、`mood_record_tags` 以及旧结构 `emotion_type_id`。
- `analysisDispatcher.ts:174` 与 `fastApiClient.ts:115` 调用 `/api/analyze/mood`，但 `mood_health_ai_service/app/main.py` 当前没有该路由。
- `analysisDispatcher` 未发现被实际业务路径导入；当前部分 AI 路由仍由 Node 直接调用旧 AI service，和“所有 AI 统一走 FastAPI”的代码注释/契约冲突。
- Node 侧旧迁移、Node 活动迁移、FastAPI 独立 SQL 形成三套未统一的表来源。

**影响**：AI 分析并非“偶发失败”，而是干净环境下无法完成 pending → processing → completed/failed 的完整闭环；不能用于毕业演示或论文能力证明。

**判定**：确定性产品/架构实现缺陷。

### P0-03：默认官方 E2E 无法证明核心业务，且注册页存在真实跳转缺陷

**现象**：官方 9 个 E2E 仅 3 个通过。注册页直接被重定向到登录页；登录后的官方 runner 又不能稳定恢复会话。

**根因边界**：

- 注册页错误是确定性产品缺陷：`/register` 是 public/guestOnly 路由，但页面初始化的 `/auth/me` 401 被全局响应拦截器按受保护页面处理，强制跳 `/login?redirect=/`。
- 官方 runner 登录后 401 与独立 Python Playwright 的成功结果矛盾。独立浏览器已经证明当前代码能设置 HttpOnly/Lax Cookie 并在硬导航后 `/auth/me` 200，因此不能武断写成“生产 Cookie 一定坏”；应先定位 Playwright storage state、请求时序、服务复用和夹具隔离。
- `playwright.config.ts:63` 注释了 `globalSetup`，默认命令也没有注入 performance spec 要求的凭据，导致默认测试本身不自包含。

**影响**：自动化门禁无法区分产品回归和测试夹具回归，心情/测评/咨询均被连带阻断。

**判定**：注册跳转为产品缺陷；登录后状态问题为测试基础设施/时序缺陷，尚不可直接归因于生产 Cookie。

## 5. P1 高优先级缺陷

### P1-01：账号删除使用旧表名且缺少可靠事务证据

`mood_health_server/src/repositories/userRepository.ts:224` 执行 `DELETE FROM mood_records WHERE user_id = ?`，当前表是 `moods`。E2E 账号清理实际返回 500。删除流程还需按当前外键依赖重新核对，并置于事务中，避免删到一半。

### P1-02：Python 质量门禁未通过

Ruff 143 个问题、Mypy 26 个问题。不能用一次 `ruff --fix` 全仓自动改完：其中字段命名可能属于 Node↔Python JSON 契约，盲目改 snake_case/camelCase 会破坏协议。必须按模块、小批次处理，每批运行 Ruff、Mypy、Pytest 和契约测试。

### P1-03：生产依赖存在已知漏洞

根项目生产依赖 2 moderate；后端生产依赖 10（含 6 high）。涉及 ECharts 链、Axios、Multer、Lodash、express-rate-limit/ip-address、form-data、path-to-regexp、qs、Morgan 等。当前报告仅证明审计命中，不证明每个漏洞都可从本项目外部利用；修复时必须看直接/传递依赖、调用点和 breaking change，禁止无评估执行 `npm audit fix --force`。

### P1-04：启动和运维契约漂移

- AI 主配置与多数新脚本使用 8001，Vite 代理、旧 `aiConfig.ts`、`dev-reset.ps1` 仍残留 8000。
- ecosystem 名称为 `mood-health-node`/`mood-health-fastapi`，package stop 脚本删除 `mood-health-server`/`mood-ai-server`，清理脚本又使用另一组名称。
- ecosystem 中 Node 健康地址和实际 `/health` 不一致。
- PM2 当前没有项目进程；Node 健康状态 degraded；FastAPI 没有监听。

### P1-05：API 错误语义和观测性不稳定

- 非法 CORS Origin 返回 500，开发响应暴露内部 CORS 文本。
- 未知 `/api/*` 返回 401 而不是 404。
- 错误处理器重新生成 request ID，使响应 header/body 不一致。
- Controller 中存在 HTTP 数字和业务码混用；日志没有稳定记录本轮 500 根因。

### P1-06：Node 测试退出不干净，集成覆盖名不副实

218 个断言虽然通过，但 Jest 明确报告异步资源未停止，命令持续约 119 秒。`test:integration` 只是再次跑 unit。数据库迁移、真实路由、Cookie/CSRF/CORS、事务和 FastAPI 调用均需要真正的集成测试层。
