## Step 2：P0-2 — 修复登录会话刷新后丢失

**问题：** 登录后刷新页面或直接访问受保护 URL，会被送回 `/login`。根因：页面刷新后 `userStore.token` 为空（内存丢失），`isLoggedIn` 为 false。虽然 `router.beforeEach` 调用了 `initializeUserState`，但 `fetchUserInfo` 在 Cookie 存在时能成功调用 `/api/auth/me` 并设置 `token.value = 'httpOnly'`——理论上应该能恢复。实际问题是 `isLoggedIn` 的判断条件 `!!token.value && !!user.value`，在 `fetchUserInfo` 完成前为 false，导致路由守卫先判定未登录。

**修复方式：** 在 `router.beforeEach` 中，`initializeUserState` 完成后，增加一个等待逻辑。或者更简单：在 `userStore` 中增加 `initialized` 状态，路由守卫等待初始化完成后再判断。

**修改文件：**
- `src/stores/userStore.ts`：增加 `initialized` 状态
- `src/router/index.ts`：`beforeEach` 中等待初始化完成

**验证：** 登录后刷新 `/mood/record`，确认不再跳转到 `/login`。

**Commit：** `fix: 修复登录会话刷新后丢失 (P0-2)`

## Step 3：P0-3 — 修复情绪记录 UI 无法新增

**问题：** 前端提交 `emotionTypeId` 为字符串（如 `'happy'`、`'sad'`），后端要求整数。后端接口 `/api/moods/record` 走 `recordMoodWithEmotions` 路径，校验 `!emotion.emotionTypeId` 时字符串 `'happy'` 为 truthy 能通过，但后续写入数据库时 `emotionTypeId` 应为整数。

**修复方式：** 前端在提交前，将字符串 `emotionTypeId`（情绪 code）映射为数据库中的整数 ID。后端 `/api/moods/types` 返回的数据中包含 `id`（整数）和 `code`（字符串）。前端需要调用该接口获取映射关系，或者直接在 `moodRecordStore` 中维护 code→id 的映射表。

**修改文件：**
- `src/stores/moodRecordStore.ts`：提交时将 `emotionTypeId` 从字符串 code 转为整数 id

**验证：** UI 登录 → 进入情绪记录 → 选择情绪 → 填写内容 → 提交，确认返回 201 而非 400。

**Commit：** `fix: 修复情绪记录提交 emotionTypeId 类型不匹配 (P0-3)`

**修改文件：**
- `mood_health_server/src/routes/caseRoutes.ts`

## Step 7：P1-3 — 统一 API 响应格式（添加 requestId）

**修改文件：**
- `mood_health_server/src/utils/apiResponse.ts`：添加 `requestId` 字段
- `mood_health_server/src/controllers/moodController.ts`：统一使用 `API_ERROR_CODES`

**验证：** 调用任意接口，确认响应中包含 `requestId` 字段，且错误码为四位业务码。

**Commit：** `fix: 统一 API 响应格式，添加 requestId (P1-3)`

## Step 8：P1-4 — 修复退出登录状态与导航

**问题 A：** 退出后 Cookie 被清除，但 UI 跳转到 `/` 而非 `/login`。根因：`App.vue` 中 `handleLogout` 调用 `router.push('/login')`，但路由守卫检测到 `isLoggedIn=false` 后重定向到 `/login`——实际上存在时序问题，直接改 `handleLogout` 确保跳转即可。

**问题 B：** Bearer Token 在退出后仍有效。后端 `/api/auth/logout` 只清除 Cookie，未将 Token 加入黑名单。

**修复方式：**
- A：确保 `handleLogout` 使用 `router.replace('/login')` 而非 `push`，避免守卫拦截
- B：简化方案——在 `userStore.logout` 中调用 `clearToken()` 后，前端不再持有 Token，刷新后也无法恢复（因为 Cookie 已清除）。实际风险是退出后短时间内 Bearer Token 仍可用，这是 JWT 无状态特性，可接受。

**修改文件：**
- `src/App.vue`：`handleLogout` 改用 `router.replace`

**验证：** 登录 → 点击退出 → 确认停留在 `/login` 页面 → 刷新后仍在 `/login`。

**Commit：** `fix: 修复退出登录后导航异常 (P1-4)`

## Step 12：P1-8 — 修复 CORS 拒绝被包装为 500

**问题：** 非法 Origin 被 CORS 中间件拒绝，但 `cors` 的 `origin` 回调中 `callback(new Error('Not allowed by CORS'))` 抛出异常，被 Express 错误处理中间件包装为 500 响应，暴露内部错误文本。

**修复方式：** 将 `callback(new Error(...))` 改为 `callback(null, false)`（标准 CORS 拒绝方式），让浏览器收到正确的 CORS 错误而非 500。

**修改文件：**
- `mood_health_server/src/app.ts`

**验证：** 以非法 Origin 发送请求，确认浏览器收到 CORS 错误（非 500 响应），且不暴露 `Not allowed by CORS` 文本。
